- 版本：1.0
- 领域：服务台
- 领域说明：服务台领域模型，涵盖工单、工单分类、服务团队、SLA策略、现场服务、技术员分配、预约
- 实体数量：30

## 实体：服务台工单（聚合根）

- 说明：服务台工单，阶段驱动状态机（New→In Progress→Solved→Closed）
- 来源：基于 沟通活动；来源域 ofbiz/party；过滤条件 沟通活动类型编号=服务请求

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 名称：文本（必填），说明 工单标题，tracked
- 说明：长文本，说明 HTML 富文本描述
- 优先级：枚举（必填），默认值 低，可选值：低 / 正常 / 高 / 紧急，说明 工单优先级
- 看板状态：枚举（必填），默认值 正常，可选值：正常 / 冻结 / 完成，说明 看板子状态，blocked 表示等待外部依赖
- 启用：布尔（必填），默认值 是，说明 归档标记（false=软删除，默认列表查询排除）
- 颜色：整数（必填），默认值 0，说明 Kanban 颜色索引
- 邮箱抄送：文本，说明 抄送邮箱列表
- 来源频道：枚举，可选值：邮箱 / 网页表单 / 门户 / 销售订单 / 在线聊天 / 手动，说明 来源渠道，由创建方式自动设定
- 创建日期：日期时间（必填、自动生成），说明 创建时间
- 分配日期：日期时间，说明 首次分配时间（仅首次分配时记录）
- 关闭日期：日期时间，说明 工单关闭时间
- 日期最近阶段更新：日期时间，说明 上次阶段变更时间
- SLA截止时间：日期时间，说明 所有 in_progress SLA 中最早的截止时间（动态计算）
- 优先级更新日期：日期时间，说明 优先级变更时间，用于 SLA 起算
- 字段服务任务数量：整数（必填），默认值 0，说明 关联现场服务任务数
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 团队：多对一 -> 服务台团队，必填关系
- 阶段：多对一 -> 服务台阶段，必填关系
- 用户：多对一 -> 参与方，外键 用户参与方编号
- 伙伴：多对一 -> 参与方，外键 伙伴参与方编号
- 工单类型：多对一 -> 服务台工单类型
- 销售订单：多对一 -> 销售订单
- 创建人：多对一 -> 参与方，外键 创建参与方编号
- SLA状态编号列表：一对多 -> 服务台SLA状态，外键 工单编号
- 工时表编号列表：一对多 -> 工时表凭证
- 字段服务任务：一对多 -> 字段服务订单
- 评级编号列表：一对多 -> 评级
- 标签编号列表：多对多 -> 服务台标签，中间关系 服务台工单标签链接

#### 唯一约束
- 唯一约束 唯一工单名称团队：名称、团队编号

### Conduct（行为声明）

#### 操作
- 创建，说明：创建工单后自动执行：
R1. 根据团队 assignment_method 自动分配负责人
R4. 遍历团队下所有 SLA 策略进行匹配
R9. 来源渠道由创建方式自动设定
，可写字段：名称、说明、优先级、来源频道、邮箱抄送，参数：团队编号：唯一标识（必填）；阶段编号：唯一标识（必填）；工单类型编号：唯一标识；伙伴编号：唯一标识；销售订单编号：唯一标识
- 查询
- 分配（类型：更新），说明：分配工单 — R1: 根据团队 assignment_method (manual/random/balanced) 分配负责人
首次分配时记录 assign_date
，参数：用户编号：唯一标识（必填）
- 变更阶段（类型：更新），说明：阶段变更 — R2: 触发副作用链
(a) 更新 date_last_stage_update
(b) 新阶段 is_close=true 时设置 close_date
(c) 从关闭阶段回退时清除 close_date
(d) 触发阶段上配置的邮件/短信模板
(e) 调用 check_sla_status() 更新所有关联 SLA
(f) 关闭且 use_customer_rating=true 时发送评分请求
，参数：阶段编号：唯一标识（必填）
- 解决（类型：更新），说明：解决工单，流转到 Solved 阶段
- 关闭（类型：更新），说明：关闭工单 — R3: 需通过 can_close_ticket? 检查
所有关联的 Field Service 任务必须已完成，否则阻止关闭

- 重新打开（类型：更新），说明：重新打开工单，清除 close_date，回到 New 阶段
- 归档（类型：更新），说明：R7 归档/软删除，设置 active=false
- 更新优先级（类型：更新），说明：更新优先级 — R5: 如果优先级更新后才匹配某个 SLA，
该 SLA 的起算时间从 priority_update_date 开始
，可写字段：优先级
- 安排现场服务（类型：更新），说明：R31/R32: 创建现场服务任务
仅当团队 use_field_service=true 时可用
自动继承客户信息、地址、描述、标签、负责人
递增 field_service_task_count


#### 校验
- 创建时，名称 不能为空（工单标题必填）
- 创建时，团队 不能为空（必须指定服务团队）
- 创建时，阶段 不能为空（必须指定阶段）
- 关闭时，存在未完成的现场服务任务，无法关闭工单
- 安排现场服务时，当前团队未启用现场服务功能

#### 策略
- 权限：创建 操作，当 操作者.角色 属于 服务台代理、服务台经理、管理员 时允许
- 权限：查询 操作，当 操作者.角色 = 管理员 或 op=relates_to_actor_via，args=创建人 时允许
- 权限：更新 操作，当 操作者.角色 = 管理员 或 op=relates_to_actor_via，args=创建人 时允许

#### 变更
- 在 创建 时，将 创建人 设为当前操作人
- 在 创建 / 变更阶段 时，将 日期最近阶段更新 设为 now()
- 在 关闭 时，将 关闭日期 设为 now()
- 在 重新打开 时，设置 关闭日期
- 在 分配 时，将 分配日期 设为 now()
- 在 更新优先级 时，将 优先级更新日期 设为 now()
- 在 归档 时，将 启用 设为 否
- 在 创建 时，回调
- 在 创建 / 更新优先级 时，回调
- 在 变更阶段 时，回调
- 在 创建 / 变更阶段 / 更新优先级 时，回调
- 在 关闭 时，回调
- 在 变更阶段 时，回调
- 在 创建 时，回调
- 在 创建 / 分配 / 变更阶段 / 解决 / 关闭 / 重新打开 / 归档 / 更新优先级 / 安排现场服务 时，将 编号 设为 编号

#### 事件
- 事件：创建 -> 服务台.工单.创建
- 事件：分配 -> 服务台.工单.已分配
- 事件：变更阶段 -> 服务台工单阶段已变更
- 事件：解决 -> 服务台工单已解决
- 事件：关闭 -> 服务台.工单.已关闭
- 事件：重新打开 -> 服务台工单已重新打开

#### 工作流
- 流程：ticket_lifecycle：创建 -> 分配 -> 变更阶段 -> 解决 -> 关闭 -> 重新打开 -> 归档 -> 更新优先级 -> 安排现场服务（工单生命周期（创建→分配→处理→解决→关闭））

## 实体：服务台SLA状态

- 说明：SLA 追踪实例，二态终结状态机（reached/failed 不可逆）
- 来源：基于 服务台SLA状态；来源域 服务台

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 截止日：日期时间（必填），说明 计算出的截止时间
- 已达到日期：日期时间，说明 实际到达目标阶段的时间
- 状态：枚举（必填），默认值 进行中，可选值：进行中 / 已达到 / 失败，说明 追踪状态 — reached 和 failed 为终态不可逆转
- 超出工时：金额，说明 超时小时数（正=提前完成/超时，视达标或失败而定）
- 排除时间工时：金额（必填），默认值 0.0，说明 累计排除的暂停时间（小时）
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 工单：多对一 -> 服务台工单，必填关系
- SLA：多对一 -> 服务台SLA，必填关系

### Conduct（行为声明）

#### 操作
- 创建，可写字段：截止日、排除时间工时，参数：工单编号：唯一标识（必填）；SLA编号：唯一标识（必填）
- 查询
- 检查并更新（类型：更新），说明：R25: 在每次阶段变更时调用，遍历工单所有 in_progress 的 SLA 追踪记录并更新状态
R26: 判定达标 — ticket.stage.sequence >= sla.reach_stage.sequence
R27: 判定失败 — now > deadline 且尚未达到目标阶段

- 标记已达到（类型：更新），说明：标记为已达标（终态不可逆），可写字段：已达到日期、超出工时
- 标记失败（类型：更新），说明：标记为已失败（终态不可逆），可写字段：超出工时
- 累计排除时间（类型：更新），说明：R29 工单进入/离开排除阶段时累加暂停工作时间，可写字段：排除时间工时

#### 校验
- 创建时，工单 不能为空
- 创建时，SLA 不能为空
- 标记已达到／标记失败时，只有 in_progress 状态的 SLA 追踪记录可以更新（终态不可逆）

#### 变更
- 在 标记已达到 时，将 状态 设为 已达到
- 在 标记失败 时，将 状态 设为 失败
- 在 创建 / 检查并更新 / 标记已达到 / 标记失败 / 累计排除时间 时，将 编号 设为 编号

#### 工作流
- 流程：sla_tracking_lifecycle：创建 -> 检查并更新 -> 标记已达到 -> 标记失败 -> 累计排除时间（SLA 追踪实例生命周期（二态终结状态机））
