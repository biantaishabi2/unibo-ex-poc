# 模型业务说明

- 版本：1.0
- 领域：质量
- 领域说明：质量管理领域模型，涵盖质量控制点、质量检查、质量警报、团队与根因分析
- 实体数量：17

## 实体：质量点（聚合根）

- 说明：质量控制点，定义何时、对什么产品、执行哪种检查，自动触发生成 QualityCheck
- 来源：基于 工作任务；来源域 ofbiz/workeffort；过滤条件 工作工作量类型编号=质量点

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 标题：文本（必填），说明 控制点名称
- 操作类型：枚举（必填），可选值：收据 / 制造 / 配送 / 内部转账，说明 操作类型，必须与触发单据类型一致
- 检查类型：枚举（必填），可选值：通过/失败 / 度量 / 图片 / 说明 / 工作表 / 打印标签，说明 检查类型
- 控制每：枚举（必填），默认值 操作，可选值：操作 / 产品 / 数量，说明 控制粒度：operation=整单一次，product=每产品一次，quantity=按数量
- 控制频率：枚举（必填），默认值 全部，可选值：全部 / 随机 / 周期性，说明 控制频率
- 频率值：金额，说明 random 时=概率%，periodic 时=间隔次数
- 标准值：金额，说明 标准值（仅 measure 类型）
- 最小容差：金额，说明 公差下限（仅 measure 类型）
- 最大容差：金额，说明 公差上限（仅 measure 类型）
- 说明：长文本，说明 检查说明/操作指引
- 失败操作：枚举（必填），默认值 警告，可选值：冻结 / 警告，说明 失败动作：block=阻塞单据，warn=仅告警
- 启用：布尔（必填），默认值 是，说明 启用状态
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 产品编号列表：多对多 -> 产品，中间关系 质量点产品链接
- 工作订单操作：多对一 -> 工作订单操作
- 团队：多对一 -> 质量团队
- 负责人：多对一 -> 参与方，外键 负责人参与方编号
- 工作表模板：多对一 -> 工作表模板
- 公司：多对一 -> 参与方，外键 公司参与方编号，必填关系
- 检查：一对多 -> 质量检查，外键 点编号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：标题、操作类型、检查类型、控制每、控制频率、频率值、标准值、最小容差、最大容差、说明、失败操作、启用，参数：公司编号：唯一标识（必填）；团队编号：唯一标识；负责人编号：唯一标识；工作表模板编号：唯一标识；产品编号列表：列表；工作订单操作编号：唯一标识
- 查询
- 更新，可写字段：标题、操作类型、检查类型、控制每、控制频率、频率值、标准值、最小容差、最大容差、说明、失败操作、启用
- 启用（类型：更新），说明：启用控制点
- 停用（类型：更新），说明：禁用控制点
- 触发检查（类型：自定义规则），说明：根据匹配规则扫描并自动生成 QualityCheck

#### 校验
- 创建时，标题 不能为空
- 创建时，操作类型 不能为空
- 创建时，检查类型 不能为空
- 创建／更新时，标准值 不能为空（measure 类型需要填写标准值），前提：check_type == 'measure'
- 创建／更新时，最小容差 不能为空（measure 类型需要填写公差下限），前提：check_type == 'measure'
- 创建／更新时，最大容差 不能为空（measure 类型需要填写公差上限），前提：check_type == 'measure'
- 创建／更新时，工作表模板编号 不能为空（worksheet 类型需要选择工作表模板），前提：check_type == 'worksheet'
- 创建／更新时，工作订单操作编号 conditional_allowed（工序关联仅在制造操作类型下有效）
- 启用时，只有已禁用的控制点可以启用
- 停用时，只有已启用的控制点可以禁用

#### 变更
- 在 启用 时，将 启用 设为 是
- 在 停用 时，将 启用 设为 否
- 在 创建 / 更新 / 启用 / 停用 / 触发检查 时，将 编号 设为 编号

#### 工作流
- 流程：quality_point_lifecycle：创建 -> 更新 -> 停用 -> 启用 -> 触发检查（质量控制点生命周期）

## 实体：质量检查（聚合根）

- 说明：质量检查记录，包含状态机 todo→pass/fail，支持 6 种检查类型
- 来源：基于 工作任务；来源域 ofbiz/workeffort；过滤条件 工作工作量类型编号=质量检查

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 名称：文本（必填、自动生成），说明 检查编号（自动生成序列号）
- 检查类型：枚举（必填），可选值：通过/失败 / 度量 / 图片 / 说明 / 工作表 / 打印标签，说明 检查类型，继承自 Point 或手动指定
- 状态：枚举（必填），默认值 待办，可选值：待办 / 通过 / 失败，说明 检查状态
- 数量已检验：金额，说明 检验数量
- 测量值：金额，说明 实测值（仅 measure 类型）
- 度量成功：枚举，可选值：通过 / 失败，说明 自动计算：tolerance_min <= measure_value <= tolerance_max → pass，否则 fail
- 图片：文本，说明 拍照记录附件路径（仅 picture 类型）
- 工作表数据：映射，说明 工作表填写数据（jsonb）
- 备注：长文本，说明 检查备注
- 参考类型：文本，说明 多态关联类型：picking / production / workorder
- 参考编号：整数，说明 多态关联 ID
- 已检查：日期时间，说明 检查完成时间
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 点：多对一 -> 质量点
- 产品：多对一 -> 产品，必填关系
- 批号：多对一 -> 批号
- 团队：多对一 -> 质量团队
- 负责人：多对一 -> 参与方，外键 负责人参与方编号
- 警报：一对多 -> 质量警报，外键 检查编号
- 公司：多对一 -> 参与方，外键 公司参与方编号，必填关系

### Conduct（行为声明）

#### 操作
- 创建，可写字段：检查类型、数量已检验、备注、参考类型、参考编号，参数：产品编号：唯一标识（必填）；公司编号：唯一标识（必填）；点编号：唯一标识；批号编号：唯一标识；团队编号：唯一标识；负责人编号：唯一标识
- 查询
- 标记通过（类型：更新），说明：执行检查——通过，可写字段：测量值、图片、工作表数据、备注
- 标记失败（类型：更新），说明：执行检查——失败，可写字段：测量值、图片、工作表数据、备注，参数：创建警报：布尔

#### 校验
- 创建时，检查类型 不能为空
- 标记通过时，只有待检查状态可以标记通过
- 标记失败时，只有待检查状态可以标记失败

#### 变更
- 在 标记通过 时，将 状态 设为 通过
- 在 标记通过 时，将 已检查 设为 当前时间
- 在 标记失败 时，将 状态 设为 失败
- 在 标记失败 时，将 已检查 设为 当前时间
- 在 标记失败 时，通话；如果 点.失败操作 = 冻结，则 无后续动作
- 在 标记失败 时，通话；如果 arguments.创建警报 = 是，则 无后续动作
- 在 创建 / 标记通过 / 标记失败 时，将 编号 设为 编号

#### 计算
- 计算字段 度量成功：枚举，规则 若 测量值 ≥ 点.最小容差 且 测量值 ≤ 点.最大容差 则 通过 否则 失败

#### 事件
- 事件：标记通过 -> 质量检查已通过
- 事件：标记失败 -> 质量检查已失败

#### 工作流
- 流程：quality_check_lifecycle：创建 -> 标记通过 -> 标记失败（质量检查生命周期）

### Conduct（行为声明）

#### 操作
- 创建，可写字段：标题、优先级、根因分析方法、说明、参考类型、参考编号，参数：公司编号：唯一标识（必填）；产品编号：唯一标识；批号编号：唯一标识；检查编号：唯一标识；团队编号：唯一标识；负责人编号：唯一标识；伙伴编号：唯一标识
- 查询
- 更新，可写字段：标题、优先级、根因分析方法、说明、纠正操作、预防性操作、验证日期、验证结果

- 在 确认 时，将 日期分配 设为 当前时间
- 在 开始进度 时，将 阶段 设为 进行中
- 在 完成 时，将 阶段 设为 完成
- 在 完成 时，将 日期关闭 设为 当前时间
- 在 确认 时，通话
- 在 创建维护请求 时，通话
- 在 开始进度 时，通话
- 在 创建 / 更新 / 确认 / 开始进度 / 完成 / 创建维护请求 时，将 编号 设为 编号

#### 事件
- 事件：确认 -> 质量.警报.已确认
- 事件：开始进度 -> 质量警报进行中
- 事件：完成 -> 质量.警报.完成

#### 工作流
- 流程：alert_lifecycle：创建 -> 确认 -> 开始进度 -> 完成（质量警报全生命周期）
