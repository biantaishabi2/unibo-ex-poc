## 实体：工程变更（聚合根）

- 说明：工程变更单，使用阶段（Stage）驱动的看板式状态机管理 BOM 变更
- 来源：基于 工程变更；来源域 产品生命周期

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 名称：文本（必填），说明 ECO 编号/名称（自动编号）
- BOM版本：整数，说明 BOM 版本号（基准+1）
- 有效期日期：日期时间，说明 生效日期（应用变更时写入）
- 备注：长文本，说明 变更说明（支持富文本）
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 类型：多对一 -> 工程变更类型，必填关系
- 阶段：多对一 -> 工程变更阶段，必填关系
- 产品模板：多对一 -> 产品模板，必填关系
- BOM：多对一 -> MRPBOM，必填关系
- 新BOM：多对一 -> MRPBOM
- 负责人：多对一 -> 参与方，外键 负责人参与方编号，必填关系
- 标签编号列表：多对多 -> 工程变更标签，中间关系 工程变更标签链接
- 审批编号列表：一对多 -> 工程变更审批，外键 工程变更编号

### Conduct（行为声明）

#### 操作
- 创建，说明：创建 ECO，自动复制基准 BOM 为修订副本，可写字段：名称、备注，参数：类型编号：唯一标识（必填）；产品模板编号：唯一标识（必填）；BOM编号：唯一标识（必填）
- 查询
- 更新，可写字段：名称、备注
- 推进阶段（类型：更新），说明：推进到下一阶段（含审批模板的阶段自动创建审批记录），参数：目标阶段编号：唯一标识（必填）
- 应用变更（类型：更新），说明：应用变更到生产 BOM（归档旧BOM、激活新BOM、写入生效日期）
- 同步基线（类型：更新），说明：同步最新生产 BOM，重新计算差异，清除冲突标记

#### 校验
- 创建时，名称 不能为空
- 应用变更时，基准 BOM 已被其他 ECO 修改，请先执行 Rebase
- 应用变更时，当前阶段不允许应用变更，或存在未通过的必要审批
- 推进阶段／更新时，终态阶段的 ECO 不可再推进或修改

#### 策略
- 权限：创建 操作，当 操作者.角色 属于 plm_engineer、管理员 时允许
- 权限：查询 操作，当 操作者.角色 = 管理员 或 op=relates_to_actor_via，args=负责人 时允许
- 权限：更新 操作，当 操作者.角色 = 管理员 或 op=relates_to_actor_via，args=负责人 时允许

#### 变更
- 在 创建 时，深拷贝基准 BOM 为修订副本（active=false），携带 bom_line_ids 和 operation_ids
- 在 创建 时，stage_id 取该类型 stage_ids 中 sequence 最小的阶段
- 在 创建 时，将 负责人 设为当前操作人
- 在 推进阶段 时，如果目标阶段含 approval_template_ids，自动创建 pending 审批记录
- 在 应用变更 时，归档旧 BOM(active=false) → 激活新 BOM(active=true, version+1) → 写入 effectivity_date
- 在 应用变更 时，更新草稿状态制造订单的 BOM 引用
- 在 应用变更 时，自动推进到 allow_apply=true 的终态阶段
- 在 同步基线 时，更新 bom_id 为最新生产 BOM，重新计算差异，清除冲突标记
- 在 创建 / 更新 / 推进阶段 / 应用变更 / 同步基线 时，将 编号 设为 编号

#### 计算
- 计算字段 看板状态：枚举，规则 若审批编号列表 中任意满足 审批编号列表.状态 = 已驳回 且 审批编号列表.审批类型 = 必填则冻结，若审批编号列表 中全部满足 审批编号列表.状态 = 已审批 且 审批编号列表.审批类型 = 必填则完成，否则正常
- 计算字段 冲突：布尔，规则 自定义规则（检查BOM冲突）
- 计算字段 允许应用：布尔，规则 阶段.允许应用 且 审批编号列表 中全部满足 审批编号列表.状态 = 已审批 且 审批编号列表.审批类型 = 必填
- 计算字段 BOM变更编号列表：列表，规则 自定义规则（BOM.BOM行编号列表，新BOM.BOM行编号列表）

#### 事件
- 事件：创建 -> 产品生命周期.工程变更.创建
- 事件：推进阶段 -> 工程变更阶段已推进
- 事件：应用变更 -> 工程变更已应用
- 事件：同步基线 -> 工程变更已同步基线

#### 工作流
- 流程：eco_lifecycle：创建 -> 推进阶段 -> 应用变更 -> 同步基线（ECO 全生命周期流程）

## 实体：工程变更审批

- 说明：ECO 审批记录，pending→approved/rejected（不可逆）
- 来源：基于 工作任务；来源域 ofbiz/workeffort；过滤条件 工作工作量类型编号=工程变更审批

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 角色：文本（必填），说明 审批角色（工程经理 / 质量经理等）
- 审批类型：枚举（必填），可选值：必填 / 可选 / 评论，说明 审批类型：required=必须 / optional=可选 / comment=仅评论
- 状态：枚举，默认值 待处理，可选值：待处理 / 已审批 / 已驳回，说明 审批状态（pending → approved / rejected，不可逆）
- 审批日期：日期时间，说明 审批完成时写入
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 工程变更：多对一 -> 工程变更，必填关系
- 审批人：多对一 -> 参与方，外键 审批人参与方编号，必填关系

### Conduct（行为声明）

#### 操作
- 创建，可写字段：角色、审批类型，参数：工程变更编号：唯一标识（必填）；审批人编号：唯一标识（必填）
- 查询
- 审批（类型：更新），说明：审批通过（不可逆）
- 驳回（类型：更新），说明：审批拒绝（不可逆）

#### 校验
- 审批／驳回时，策略检查（只有指定的审批人可以执行审批操作）
- 审批时，只有待审批状态可以通过
- 驳回时，只有待审批状态可以拒绝

#### 策略
- 权限：审批 操作，当 操作者.编号 = 数据.审批人编号 时允许
- 权限：驳回 操作，当 操作者.编号 = 数据.审批人编号 时允许

#### 变更
- 在 审批 时，将 状态 设为 已审批
- 在 审批 时，将 审批日期 设为 当前时间
- 在 驳回 时，将 状态 设为 已驳回
- 在 驳回 时，将 审批日期 设为 当前时间
- 在 创建 / 审批 / 驳回 时，将 编号 设为 编号

#### 工作流
- 流程：eco_approval_decision_flow：创建 -> 审批 -> 驳回（ECO 审批决策流程）

## 实体：BOM版本

- 说明：BOM 版本管理扩展，追踪版本链路和变更历史
- 来源：基于 MRPBOM；来源域 产品生命周期

### Schema（数据模型）

#### 字段
- 版本：整数，默认值 1，说明 BOM 版本号，ECO 应用变更时自增（只增不减）
- 启用：布尔，默认值 是，说明 是否为当前生产版本（同一产品同一时间仅一个 active=true）
- 变更说明：长文本，说明 版本变更描述（来自 ECO.note）
- 有效期类型：枚举，默认值 日期，可选值：日期 / 序列号范围 / 批号，说明 生效类型（初期仅实现 date 模式）

#### 关系
- 工程变更：多对一 -> 工程变更

### Conduct（行为声明）

#### 校验
- 创建／更新时，同一产品同一时间只能有一个激活的 BOM
- 更新时，BOM 版本号只能递增，不可回退

#### 工作流
- 流程：BOM激活同步：evaluate_activation -> sync_draft_mo（BOM 激活后同步草稿制造单）
- 流程：bom_where_used_analysis：collect_component_usages -> build_recursive_bom_tree（BOM where-used 反查流程）
- 流程：bom_component_delta_impact：detect_component_delta -> 同步采购库存影响（BOM 组件增删导致的供应链影响评估）
