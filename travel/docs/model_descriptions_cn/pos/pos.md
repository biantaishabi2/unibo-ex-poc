# 模型业务说明

- 版本：1.0
- 领域：
- 领域说明：销售终端领域模型，涵盖 POS 会话、订单、订单行、付款、餐饮楼层与餐桌
- 实体数量：13

## 实体：会话（聚合根）

- 说明：POS 会话，管理收银台从开启到关闭的完整生命周期
- 来源：基于 工作任务；来源域 ofbiz/workeffort；过滤条件 工作工作量类型编号=POS会话

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 会话编码：文本（必填），说明 会话编号，全局唯一
- 状态：枚举，默认值 期初，可选值：期初 / 打开 / 期末 / 已关闭，说明 会话状态
- 期初余额：金额，默认值 0，说明 期初余额，从上一个 session 继承
- 期末余额已盘点：金额，说明 实际盘点余额
- 期末余额理论：金额，说明 理论余额 = opening_balance + sum(cash_statement_lines.amount)
- 现金差额：金额，说明 差异 = closing_balance_theoretical - closing_balance_counted
- 打开日期：日期时间（必填），说明 开启时间
- 关闭日期：日期时间，说明 关闭时间
- 救援：布尔，默认值 否，说明 是否救援会话（订单到达已关闭会话时自动创建）
- 备注：长文本，说明 备注
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 订单：一对多 -> 订单，外键 会话编号
- 收银员：多对一 -> 参与方，外键 收银员参与方编号
- 公司参与方：多对一 -> 参与方，外键 公司参与方编号
- 配置：多对一 -> 配置

#### 唯一约束
- 唯一约束 唯一会话编码：会话编码

### Conduct（行为声明）

#### 操作
- 创建，可写字段：会话编码、配置编号、公司参与方编号、期初余额、打开日期、救援、备注
- 查询
- 打开（类型：更新），说明：打开会话，期初余额默认继承同 config 上一个 closed 会话的 closing_balance_counted，可写字段：期初余额
- 开始关闭（类型：更新），说明：开始关闭会话（进入 closing 状态）
- 关闭（类型：更新），说明：关闭会话，触发会计分录、对账、库存拣货，可写字段：期末余额已盘点

#### 校验
- 创建时，会话编码 不能为空
- 创建／打开时，每个终端同一时刻最多一个非救援的活跃会话
- 创建／打开时，开启日期必须晚于公司会计锁定日期
- 打开时，只有开启中状态可以打开
- 开始关闭时，只有已打开状态可以开始关闭
- 开始关闭时，存在草稿状态订单，无法开始关闭
- 关闭时，只有关闭中状态可以关闭
- 关闭时，存在未过账发票，无法关闭会话

#### 策略
- 权限：创建 操作，当 操作者.角色 属于 收银员、经理、管理员 时允许
- 权限：查询 操作，当 操作者.角色 = 管理员 或 op=relates_to_actor_via，args=公司参与方 时允许
- 权限：更新 操作，当 操作者.角色 = 管理员 或 op=relates_to_actor_via，args=公司参与方 时允许

#### 变更
- 在 创建 时，将 收银员 设为当前操作人
- 在 打开 时，将 期初余额 设为 coalesce（期初余额，最近已关闭会话余额(配置编号)，0）
- 在 打开 时，将 状态 设为 打开
- 在 开始关闭 时，将 状态 设为 期末
- 在 关闭 时，将 状态 设为 已关闭
- 在 关闭 时，将 关闭日期 设为 当前时间
- 在 关闭 时，副作用
- 在 关闭 时，副作用
- 在 关闭 时，副作用
- 在 关闭 时，副作用
- 在 关闭 时，副作用
- 在 关闭 时，副作用
- 在 创建 / 打开 / 开始关闭 / 关闭 时，将 编号 设为 编号

#### 工作流
- 流程：session_lifecycle：创建 -> 打开 -> 开始关闭 -> 关闭（POS 会话生命周期（opening→open→closing→closed））

## 实体：订单（聚合根）

- 说明：POS 订单，支持正常销售、退款、开票完整流程
- 来源：基于 订单表头；来源域 ofbiz/order；过滤条件 销售频道枚举编号=销售频道

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 订单单号：文本（必填），说明 订单号，唯一
- 状态：枚举，默认值 草稿，可选值：草稿 / 已付清 / 完成 / 已开票 / 取消，说明 状态机: draft→paid→done→invoiced, draft→cancel, done→invoiced
- 金额合计：金额，说明 含税总额 = sum(lines.price_subtotal_incl)
- 税额：金额，说明 税额 = sum(lines.price_subtotal_incl) - sum(lines.price_subtotal)
- 金额未税：金额，说明 不含税小计 = sum(lines.price_subtotal)
- 金额已付清：金额，说明 已付金额 = sum(payments.amount)
- 金额变更：金额，说明 找零金额 = max(0, amount_paid - amount_total)
- 折扣金额：金额，默认值 0，说明 折扣总额
- 币种费率：金额，说明 订单币种→公司本币汇率（当日）
- 已开票：布尔，说明 是否已开发票（account_move_id IS NOT NULL）
- 已退款：布尔，说明 是否全部退款
- 客户数量：整数，默认值 0，说明 就餐人数
- 利润率：金额，说明 毛利 = sum(lines.margin)
- 利润率百分比：金额，说明 毛利率 = margin / amount_untaxed * 100
- 订单日期：日期时间（必填），说明 下单时间
- 备注：长文本，说明 备注
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 项目：一对多 -> 订单行，外键 订单编号，管理模式 直接管理
- 付款：一对多 -> 付款，外键 订单编号
- 会话：多对一 -> 会话，必填关系
- 伙伴：多对一 -> 参与方，外键 伙伴参与方编号
- 公司参与方：多对一 -> 参与方，外键 公司参与方编号
- 币种：多对一 -> 币种，必填关系
- 税务位置：多对一 -> 财务岗位
- 表：多对一 -> RestaurantTable
- 已退款订单：多对一 -> 订单
- 退款订单：一对多 -> 订单，外键 已退款订单编号

#### 唯一约束
- 唯一约束 唯一订单单号：订单单号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：订单单号、订单日期、公司参与方编号、折扣金额、币种编号、税务位置编号、伙伴编号、客户数量、备注，参数：项目：列表（必填）；会话编号：唯一标识（必填）；表编号：唯一标识
- 查询
- 付款（类型：更新），说明：标记已付款，清理并重建 payment 记录，实时模式下触发库存拣货，参数：付款：列表（必填）
- 完成（类型：更新），说明：标记订单完成（会话关闭时批量处理）
- 发票（类型：更新），说明：开具发票，生成 account.move，可写字段：伙伴编号
- 退款（类型：创建），说明：创建退款单（数量/金额取反的镜像订单），参数：退款明细行：列表
- 取消（类型：更新），说明：取消订单
- 删除，说明：删除订单（仅 draft 或 cancel 状态）

#### 校验
- 创建时，订单单号 不能为空
- 付款时，支付金额不足（允许现金舍入容差）
- 付款时，只有草稿状态可以付款
- 完成时，只有已付款状态可以标记完成
- 发票时，伙伴编号 不能为空（开发票必须指定客户）
- 发票时，只有完成状态可以开票
- 取消时，只有草稿状态可以取消
- 删除时，仅草稿或取消状态可删除

#### 策略
- 权限：创建 操作，当 操作者.角色 属于 收银员、经理、管理员 时允许
- 权限：查询 操作，当 操作者.角色 = 管理员 或 op=relates_to_actor_via，args=公司参与方 时允许
- 权限：更新 操作，当 操作者.角色 = 管理员 或 op=relates_to_actor_via，args=公司参与方 时允许

#### 变更
- 在 创建 时，将 金额合计 设为 合计(项目.价格小计含)
- 在 创建 时，将 金额未税 设为 合计(项目.价格小计)
- 在 创建 时，将 税额 设为 金额合计 - 金额未税
- 在 付款 时，副作用
- 在 付款 时，副作用
- 在 付款 时，将 状态 设为 已付清
- 在 付款 时，副作用
- 在 完成 时，将 状态 设为 完成
- 在 发票 时，副作用
- 在 发票 时，副作用
- 在 发票 时，将 状态 设为 已开票
- 在 退款 时，副作用
- 在 退款 时，副作用
- 在 取消 时，将 状态 设为 取消
- 在 创建 / 付款 / 完成 / 发票 / 退款 / 取消 / 删除 时，将 编号 设为 编号

#### 工作流
- 流程：订单流程：创建 -> 付款 -> 完成 -> 发票 -> 退款 -> 取消 -> 删除（POS 订单流程（draft→paid→done→invoiced / draft→cancel））

## 实体：订单行

- 说明：POS 订单行，记录单个商品的销售明细
- 来源：基于 订单项；来源域 ofbiz/order

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 产品名称：文本（必填），说明 产品名称（快照）
- 产品编码：文本，说明 产品编码
- 数量：金额（必填），说明 数量（退款时为负）
- 单价：金额（必填），必须 ≥ 0（单价不能为负），说明 单价
- 折扣：金额，默认值 0，必须 ≥ 0（折扣不能为负），必须 ≤ 100（折扣不能超过100%），说明 折扣百分比 (0-100)
- 价格小计：金额，说明 不含税小计
- 价格小计含：金额，说明 含税小计
- 税编号列表：uuid[]，说明 关联税率列表
- 成本价格：金额，说明 成本价（用于毛利计算）
- 利润率：金额，说明 行毛利
- 利润率百分比：金额，说明 行毛利率
- 备注：文本，说明 服务员内部备注（餐饮模式）
- 批号名称：文本，说明 批次/序列号
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 订单：多对一 -> 订单，必填关系
- 产品：多对一 -> 产品，必填关系
- 已退款订单行：多对一 -> 订单行
- 退款订单行：一对多 -> 订单行，外键 已退款订单行编号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：产品编号、产品名称、产品编码、数量、单价、折扣、税编号列表、成本价格、备注、批号名称
- 更新，可写字段：数量、单价、折扣

#### 校验
- 数量不能为零
- 退款行必须关联原始订单行
- 启用批次/序列号追踪的产品必须填写 lot_name

#### 变更
- 在 创建 / 更新 时，将 价格小计含 设为 数量 × 单价 × 1 - 折扣 ÷ 100
- 在 创建 / 更新 时，将 价格小计 设为 税排除(价格小计含, 税编号列表)
- 在 创建 / 更新 时，将 利润率 设为 价格小计 - 成本价格 × abs(数量)
- 在 创建 / 更新 时，将 编号 设为 编号

#### 工作流
- 流程：orderline_management：创建 -> 更新（订单行管理（创建→修改））

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 名称：文本（必填），说明 楼层名称
- 背景图片：二进制，说明 楼层背景图
- 背景颜色：文本，默认值 rgb(210, 210, 210)，说明 背景色（CSS 格式）
- 序列：整数，默认值 1，说明 排序序号
- 启用：布尔，默认值 是，说明 是否启用
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- tables：一对多 -> RestaurantTable，外键 floor_id
- 配置链接：一对多 -> PosConfigFloor，外键 floor_id

### Conduct（行为声明）

#### 操作
- 创建，可写字段：名称、背景图片、背景颜色、序列、启用
- 查询
- 更新，可写字段：名称、背景图片、背景颜色、序列、启用
- 停用（类型：更新），说明：停用楼层，级联停用所有餐桌（需先检查无草稿订单）
- 删除，说明：删除楼层（有活跃会话时禁止删除）

#### 校验
- 创建时，名称 不能为空
- 停用时，楼层下存在草稿订单，无法停用
- 删除时，关联的 POS 配置存在活跃会话，无法删除楼层

#### 变更
- 在 停用 时，将 启用 设为 否
- 在 停用 时，副作用
- 在 创建 / 更新 / 停用 / 删除 时，将 编号 设为 编号

#### 工作流
- 流程：floor_lifecycle：创建 -> 更新 -> 停用 -> 删除（餐饮楼层生命周期）

## 实体：RestaurantTable

- 说明：餐桌，记录餐桌的布局位置、形状、座位数等信息
- 来源：基于 设施位置；来源域 ofbiz/product

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 名称：文本（必填），说明 餐桌名称
- 餐桌形状（shape）：枚举，默认值 square，可选值：square / 四舍五入
- 席位：整数，默认值 1，必须 ≥ 1（座位数至少为1），说明 座位数
- 水平位置（像素）（position_h）：金额，默认值 10
- 垂直位置（像素）（position_v）：金额，默认值 10
- 宽度：金额，默认值 50，说明 宽度（像素）
- 高度：金额，默认值 50，说明 高度（像素）
- 颜色：文本，默认值 #35D374，说明 颜色（CSS 格式）
- 启用：布尔，默认值 是，说明 是否启用
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- floor：多对一 -> RestaurantFloor，必填关系
- 订单：一对多 -> 订单，外键 表编号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：名称、shape、席位、position_h、position_v、宽度、高度、颜色、启用，参数：floor_id：唯一标识（必填）
- 查询
- 更新，可写字段：名称、shape、席位、position_h、position_v、宽度、高度、颜色、启用
- 删除，说明：删除餐桌（有活跃会话时禁止删除）

#### 校验
- 创建时，名称 不能为空
- 删除时，关联的 POS 配置存在活跃会话，无法删除餐桌

#### 变更
- 在 创建 / 更新 / 删除 时，将 编号 设为 编号

#### 工作流
- 流程：table_management：创建 -> 更新 -> 删除（餐桌管理）
