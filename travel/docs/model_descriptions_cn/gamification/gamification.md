# 模型业务说明

- 版本：1.0
- 领域：Gamification
- 领域说明：游戏化激励领域模型，涵盖目标定义与追踪、挑战管理、勋章授予、Karma积分与段位系统
- 实体数量：13

## 实体：GoalDefinition（聚合根）

- 说明：目标定义模板，支持4种计算模式（手动/计数/求和/Python脚本）
- 来源：基于 GoalDefinition；来源域 gamification/gamification

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 名称：文本（必填），说明 目标定义名称
- 说明：长文本，说明 目标描述
- 是否为货币值（monetary）：布尔，默认值 否
- 后缀：文本，说明 单位后缀
- 计算方式（手动/计数/求和/Python脚本）（computation_mode）：枚举（必填），默认值 manually，可选值：manually / 数量 / 合计 / python
- 显示模式：枚举，默认值 进度，可选值：进度 / 布尔，说明 展示方式（进度条/布尔达成）
- 域：文本，默认值 []，说明 过滤域表达式
- 批次模式：布尔，默认值 否，说明 是否批量评估
- 批次用户表达式：文本，说明 批量模式下用户表达式
- 计算编码：长文本，说明 Python代码（computation_mode=python时使用）
- 条件：枚举，默认值 higher，可选值：higher / lower，说明 目标方向（越高越好/越低越好）
- 资源编号字段：文本，说明 用户profile上的res_id字段名
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- goals：一对多 -> Goal，外键 definition_id
- challenge_lines：一对多 -> ChallengeLine，外键 definition_id

### Conduct（行为声明）

#### 操作
- 创建，可写字段：名称、说明、monetary、后缀、computation_mode、显示模式、域、批次模式、批次用户表达式、计算编码、条件、资源编号字段
- 查询
- 更新，可写字段：名称、说明、monetary、后缀、computation_mode、显示模式、域、批次模式、批次用户表达式、计算编码、条件、资源编号字段
- 删除

#### 校验
- 创建时，名称 不能为空
- 创建时，computation_mode 不能为空

#### 变更
- 在 创建 / 更新 / 删除 时，将 编号 设为 编号

#### 计算
- 计算字段 完整后缀：文本，规则 计算完整后缀(monetary, 后缀)

#### 工作流
- 流程：goal_definition_lifecycle_flow：创建 -> 更新 -> 删除（目标定义创建、更新与删除流程）

## 实体：Goal

- 说明：目标实例，记录用户在特定时间段的目标进度和状态
- 来源：基于 Goal；来源域 gamification/gamification

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 开始日期：日期，说明 开始日期
- 结束日期：日期，说明 结束日期
- 目标值（target_goal）：浮点（必填）
- 当前：浮点（必填），默认值 0，说明 当前值
- 状态：枚举（必填），默认值 草稿，可选值：草稿 / inprogress / 已达到 / 失败 / 已取消，说明 目标状态
- 更新：布尔，默认值 否，说明 需要更新标记
- 已关闭：布尔，默认值 否，说明 是否已关闭
- 手动目标提醒延迟天数（remind_update_delay）：整数
- 最近更新：日期，说明 最后更新日期
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- definition：多对一 -> GoalDefinition，必填关系
- 用户：多对一 -> 参与方，外键 用户参与方编号，必填关系
- 行：多对一 -> ChallengeLine

### Conduct（行为声明）

#### 操作
- 创建，可写字段：开始日期、结束日期、target_goal、当前、状态、remind_update_delay，参数：definition_id：唯一标识（必填）；用户编号：唯一标识（必填）；行编号：唯一标识
- 查询
- 更新，可写字段：当前、状态、更新、已关闭、最近更新、remind_update_delay
- 操作开始（类型：更新），说明：启动目标（draft -> inprogress）
- 操作触达（类型：更新），说明：标记达成（inprogress -> reached）
- 操作失败（类型：更新），说明：标记失败（inprogress -> failed）
- 操作取消（类型：更新），说明：取消目标（任意状态 -> canceled）

#### 校验
- 创建时，target_goal 不能为空
- 操作开始时，只有草稿状态可以启动
- 操作触达时，只有进行中状态可以标记达成
- 操作失败时，只有进行中状态可以标记失败

#### 变更
- 在 操作开始 时，将 状态 设为 inprogress
- 在 操作触达 时，将 状态 设为 已达到
- 在 操作触达 时，将 已关闭 设为 是
- 在 操作失败 时，将 状态 设为 失败
- 在 操作失败 时，将 已关闭 设为 是
- 在 操作取消 时，将 状态 设为 已取消
- 在 操作取消 时，将 已关闭 设为 是
- 在 创建 / 更新 / 操作开始 / 操作触达 / 操作失败 / 操作取消 时，将 编号 设为 编号

#### 计算
- 计算字段 completeness：浮点，规则 当前 ÷ target_goal × 100

#### 事件
- 事件：操作触达 -> gamification.goal.已达到
- 事件：操作失败 -> gamification.goal.失败

#### 工作流
- 流程：goal_flow：创建 -> 更新 -> 操作开始 -> 操作触达 -> 操作失败 -> 操作取消（目标生命周期流程）

## 实体：Challenge（聚合根）

- 说明：挑战，包含参与者、目标行列表、周期配置和奖励规则
- 来源：基于 Challenge；来源域 gamification/gamification

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 名称：文本（必填），说明 挑战名称
- 说明：长文本，说明 挑战描述
- 状态：枚举（必填），默认值 草稿，可选值：草稿 / inprogress / 完成，说明 挑战状态

- 期间：枚举，默认值 once，可选值：once / 每日 / 每周 / 月度 / 年度，说明 挑战周期
- 开始日期：日期，说明 开始日期
- 结束日期：日期，说明 结束日期
- 奖励失败：布尔，默认值 否，说明 未全部成功时是否也奖励最佳用户
- 达标后是否即时奖励（reward_realtime）：布尔，默认值 是
- 可见性模式：枚举，默认值 私有，可选值：私有 / ranking，说明 可见模式（个人/排名）
- 报表消息频率：枚举，默认值 never，可选值：never / onchange / 每日 / 每周 / 月度 / 年度，说明 报告频率

- 最近报表日期：日期，说明 上次报告日期
- 挑战分类（challenge_category）：枚举，默认值 其他，可选值：人力 / 其他
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 经理：多对一 -> 参与方，外键 经理参与方编号
- 奖励：多对一 -> 徽章
- 奖励首个：多对一 -> 徽章
- 奖励第二：多对一 -> 徽章
- 奖励第三：多对一 -> 徽章
- 行编号列表：一对多 -> ChallengeLine，外键 challenge_id
- 用户编号列表：多对多 -> 参与方，外键 用户编号列表参与方编号，中间关系 ChallengeUserLink
- 已邀请用户编号列表：多对多 -> 参与方，外键 已邀请用户编号列表参与方编号，中间关系 ChallengeInvitedUserLink

### Conduct（行为声明）

#### 操作
- 创建，可写字段：名称、说明、状态、用户域、期间、开始日期、结束日期、奖励失败、reward_realtime、可见性模式、报表消息频率、remind_update_delay、challenge_category，参数：经理编号：唯一标识；奖励编号：唯一标识；奖励首个编号：唯一标识；奖励第二编号：唯一标识；奖励第三编号：唯一标识
- 查询
- 更新，可写字段：名称、说明、用户域、期间、开始日期、结束日期、奖励失败、reward_realtime、可见性模式、报表消息频率、remind_update_delay、challenge_category，参数：经理编号：唯一标识；奖励编号：唯一标识；奖励首个编号：唯一标识；奖励第二编号：唯一标识；奖励第三编号：唯一标识
- 操作开始（类型：更新），说明：启动挑战（draft -> inprogress）
- 操作检查（类型：更新），说明：检查挑战进度并触发奖励评估
- 完成操作（类型：更新），说明：完成挑战（inprogress -> done）

#### 校验
- 创建时，名称 不能为空
- 操作开始时，只有草稿状态可以启动
- 完成操作时，只有进行中状态可以完成

#### 变更
- 在 操作开始 时，将 状态 设为 inprogress
- 在 完成操作 时，将 状态 设为 完成
- 在 创建 / 更新 / 操作开始 / 操作检查 / 完成操作 时，将 编号 设为 编号

#### 计算
- 计算字段 用户数量：整数
- 计算字段 下一个报表日期：日期，规则 计算下一个报表日期(报表消息频率, 最近报表日期)

#### 事件
- 事件：操作开始 -> gamification.challenge.开始
- 事件：完成操作 -> gamification.challenge.完成

#### 工作流
- 流程：challenge_flow：创建 -> 更新 -> 操作开始 -> 操作检查 -> 完成操作（挑战生命周期流程）
