# 模型业务说明

- 版本：1.0
- 领域：Loyalty
- 领域说明：积分/优惠券/礼品卡领域模型，涵盖积分计划定义、会员卡、规则引擎、积分流水、优惠券发放与核销、礼品卡充值与消费
- 实体数量：11

## 实体：LoyaltyProgram（聚合根）

- 说明：积分计划主体，定义积分获取与消耗规则，支持电商/POS/销售多渠道
- 来源：基于 产品促销；来源域 ofbiz/product；过滤条件 用户已录入=否

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 名称：文本（必填），说明 计划名称（如"VIP会员积分计划"）
- 说明：长文本，说明 计划说明
- 项目集类型：枚举（必填），默认值 积分，可选值：积分 / cashback / 折扣 / mixed，说明 计划类型（积分/现金返还/折扣/混合）
- 状态：枚举（必填），默认值 草稿，可选值：草稿 / 启用 / 暂停 / 已过期，说明 计划状态
- 积分币种名称：文本，默认值 积分，说明 积分单位名称（积分/里程/金币）
- 积分每币种：金额，默认值 1.0，必须大于 0（积分兑换率必须大于0），说明 每消费1元获得的积分数，源自 ProductPromo.billback_factor
- 需求编码：布尔，默认值 否，说明 是否需要优惠码才能参与（映射 ProductPromo.require_code）
- 使用限制每订单：整数，说明 每订单最大使用次数（映射 ProductPromo.use_limit_per_order）
- 使用限制每客户：整数，说明 每客户最大参与次数（映射 ProductPromo.use_limit_per_customer）
- 使用限制每项目集：整数，说明 计划全局使用上限（映射 ProductPromo.use_limit_per_promotion）
- 来源日期：日期，说明 计划生效日期
- 至日期：日期，说明 计划终止日期
- 门户可见：布尔，默认值 是，说明 是否在客户门户显示（映射 ProductPromo.show_to_customer）
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 规则：一对多 -> LoyaltyRule，外键 项目集编号
- rewards：一对多 -> LoyaltyReward，外键 项目集编号
- coupons：一对多 -> Coupon，外键 项目集编号
- cards：一对多 -> LoyaltyCard，外键 项目集编号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：名称、说明、项目集类型、积分币种名称、积分每币种、需求编码、使用限制每订单、使用限制每客户、使用限制每项目集、来源日期、至日期、门户可见
- 查询
- 更新，可写字段：名称、说明、项目集类型、积分每币种、使用限制每订单、使用限制每客户、至日期、门户可见
- 启用（类型：更新），说明：激活计划（draft/paused -> active），可写字段：来源日期
- 暂停（类型：更新），说明：暂停计划（active -> paused）
- 过期（类型：更新），说明：终止计划（任意 -> expired），可写字段：至日期
- 删除

#### 校验
- 创建时，名称 不能为空
- 创建时，项目集类型 不能为空

#### 变更
- 在 启用 时，将 状态 设为 启用
- 在 暂停 时，将 状态 设为 暂停
- 在 过期 时，将 状态 设为 已过期
- 在 创建 / 更新 / 删除 时，将 编号 设为 编号

#### 事件
- 事件：启用 -> loyalty.项目集.已激活
- 事件：过期 -> loyalty.项目集.已过期

#### 工作流
- 流程：program_lifecycle_flow：创建 -> 更新 -> 启用 -> 暂停 -> 过期（积分计划生命周期流程）

## 实体：LoyaltyCard

- 说明：会员积分卡，记录持卡人当前积分余额与生命周期状态
- 来源：基于 参与方角色；来源域 ofbiz/party；关联 参与方角色（用户已录入=否）

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 卡单号：文本（必填），说明 卡号（唯一，系统自动生成）
- 状态：枚举（必填），默认值 启用，可选值：启用 / frozen / 已过期 / 已取消，说明 卡状态
- 积分余额：金额（必填），默认值 0，必须 ≥ 0（积分余额不能为负），说明 当前积分余额
- 历史累计获取积分（用于升级判断）（lifetime_points_earned）：金额，默认值 0
- 过期日期：日期，说明 积分卡到期日
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 项目集：多对一 -> LoyaltyProgram，必填关系
- transactions：一对多 -> LoyaltyTransaction，外键 卡编号

#### 唯一约束
- 唯一约束 唯一卡单号：卡单号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：卡单号、过期日期，参数：项目集编号：唯一标识（必填）；伙伴编号：唯一标识（必填）
- 查询
- earn_points（类型：更新），说明：增加积分（消费/活动奖励），触发 LoyaltyTransaction 写入，可写字段：积分余额、lifetime_points_earned，参数：points_delta：金额（必填）；订单编号：唯一标识；原因：文本
- redeem_points（类型：更新），说明：扣减积分（兑换奖励），余额不足则拒绝，可写字段：积分余额，参数：points_delta：金额（必填）；奖励编号：唯一标识
- freeze（类型：更新），说明：冻结积分卡（active -> frozen）
- unfreeze（类型：更新），说明：解冻积分卡（frozen -> active）
- 过期卡（类型：更新），说明：到期处理，清零余额（active -> expired），可写字段：过期日期

#### 变更
- 在 freeze 时，将 状态 设为 frozen
- 在 unfreeze 时，将 状态 设为 启用
- 在 过期卡 时，将 状态 设为 已过期
- 在 创建 / 更新 / earn_points / redeem_points 时，将 编号 设为 编号

#### 计算
- 计算字段 points_to_next_tier：金额，规则 compute_points_to_next_tier(lifetime_points_earned)

#### 事件
- 事件：earn_points -> loyalty.积分.earned
- 事件：redeem_points -> loyalty.积分.redeemed

#### 工作流
- 流程：card_lifecycle_flow：创建 -> earn_points -> redeem_points -> freeze -> unfreeze -> 过期卡（会员积分卡生命周期流程）

## 实体：LoyaltyRule

- 说明：积分规则，定义触发积分奖励的条件（消费阈值、品类、渠道、时间窗口），源自 OFBiz ProductPromoRule + ProductPromoCond
- 来源：基于 产品促销规则；来源域 ofbiz/product；关联 产品促销条件

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 规则名称：文本（必填），说明 规则名称（映射 ProductPromoRule.rule_name）
- 规则类型：枚举（必填），可选值：最小订单金额 / 产品分类 / 频道 / 时间窗口 / 自定义规则，说明 规则类型（最低消费/品类/渠道/时间窗/自定义，映射 ProductPromoCond.input_param_enum_id）
- 操作员：枚举，默认值 大于等于，可选值：等于 / 大于 / 大于等于 / 小于 / 小于等于 / 包含 / 非包含，说明 比较运算符（映射 ProductPromoCond.operator_enum_id）
- 条件值：文本，说明 条件值（映射 ProductPromoCond.cond_value），如 "100.00" 或 "CATEGORY_A,CATEGORY_B"
- 其他值：文本，说明 辅助条件值（映射 ProductPromoCond.other_value），如上限金额
- 积分倍数：金额，默认值 1.0，必须大于 0（积分倍率必须大于0），说明 满足条件时的积分倍率（如双倍积分填 2.0）
- 奖金积分：金额，默认值 0，说明 满足条件时的固定奖励积分
- 启用：布尔，默认值 是
- 优先级：整数，默认值 10，说明 规则优先级，数字越小越先评估
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 项目集：多对一 -> LoyaltyProgram，必填关系

### Conduct（行为声明）

#### 操作
- 创建，可写字段：规则名称、规则类型、操作员、条件值、其他值、积分倍数、奖金积分、启用、优先级，参数：项目集编号：唯一标识（必填）
- 查询
- 更新，可写字段：规则名称、条件值、其他值、积分倍数、奖金积分、启用、优先级
- 删除

#### 校验
- 创建时，规则名称 不能为空
- 创建时，条件值 不能为空

#### 变更
- 在 创建 / 更新 / 删除 时，将 编号 设为 编号

#### 计算
- 计算字段 生效积分：金额，规则 计算生效积分(积分倍数, 奖金积分)

#### 工作流
- 流程：rule_lifecycle_flow：创建 -> 更新 -> 删除（积分规则创建、更新与删除流程）

## 实体：LoyaltyTransaction

- 说明：积分流水，记录积分的每次变动（获取/消耗/过期/退款），是积分生命周期的审计日志
- 来源：基于 产品促销使用；来源域 ofbiz/product；关联 产品促销使用

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 交易类型：枚举（必填），可选值：earned / redeemed / 已过期 / 已退款 / adjusted / transferred，说明 流水类型（获取/消耗/过期/退款/人工调整/转移）
- 积分变动量（正数=增加，负数=减少；扩展 ProductPromoUse.total_discount_amount）（points_delta）：金额（必填）
- 余额后：金额（必填），说明 本次操作后的积分余额快照
- 流水状态（pending=待确认，confirmed=已确认，cancelled=已撤销）（lifecycle_status）：枚举（必填），默认值 已确认，可选值：待处理 / 已确认 / 已取消
- 参考号类型：文本，说明 关联业务类型（order/return/admin_adjustment）
- 参考号编号：文本，说明 关联业务 ID（映射 ProductPromoUse.order_id）
- 促销编码已用：文本，说明 使用的优惠码（映射 ProductPromoUse.product_promo_code_id）
- 备注：文本，说明 备注说明
- 过期：日期时间，说明 本批次积分的过期时间（earned 类型专用）
- 创建时间：日期时间（自动生成）

#### 关系
- 卡：多对一 -> LoyaltyCard，必填关系
- 奖励：多对一 -> LoyaltyReward

### Conduct（行为声明）

#### 操作
- 创建，可写字段：交易类型、points_delta、余额后、参考号类型、参考号编号、促销编码已用、备注、过期，参数：卡编号：唯一标识（必填）；伙伴编号：唯一标识（必填）；奖励编号：唯一标识
- 查询
- 取消交易（类型：更新），说明：撤销流水（confirmed -> cancelled），同步回滚积分卡余额，可写字段：备注

#### 校验
- 创建时，points_delta 不能为空
- 创建时，交易类型 不能为空

#### 变更
- 在 取消交易 时，将 lifecycle_status 设为 已取消
- 在 创建 / 取消交易 时，将 编号 设为 编号

#### 事件
- 事件：创建 -> loyalty.交易.创建
- 事件：取消交易 -> loyalty.交易.已取消

#### 工作流
- 流程：transaction_flow：创建 -> 取消交易（积分流水创建与撤销流程）

## 实体：Coupon（聚合根）

- 说明：优惠券，携带唯一码、有效期、使用次数限制，支持通用码与专属码两种模式
- 来源：基于 产品促销码；来源域 ofbiz/product

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 编码：文本（必填），说明 优惠码（映射 ProductPromoCode.product_promo_code_id，唯一索引）
- 券类型（public=通用码/private=专属码需绑定用户/one_time=一次性）（coupon_type）：枚举（必填），默认值 公开，可选值：公开 / 私有 / 一时间
- 状态：枚举（必填），默认值 启用，可选值：启用 / 已用 / 已过期 / 已取消，说明 券状态
- 折扣类型：枚举，可选值：百分比 / 固定 / free_shipping，说明 折扣方式
- 折扣值：金额，必须大于 0（折扣值必须大于0），说明 折扣值（百分比或固定金额）
- 最小订单金额：金额，说明 最低使用门槛
- 最大折扣金额：金额，说明 最大折扣上限
- 使用限制每编码：整数，说明 全局使用次数上限（映射 ProductPromoCode.use_limit_per_code）
- 使用限制每客户：整数，默认值 1，说明 每客户使用次数上限（映射 ProductPromoCode.use_limit_per_customer）
- 已用数量：整数，默认值 0，说明 已使用次数
- 来源日期：日期时间，说明 生效时间（映射 ProductPromoCode.from_date）
- 至日期：日期时间，说明 过期时间（映射 ProductPromoCode.thru_date）
- 需求邮箱或参与方：布尔，默认值 否，说明 是否要求绑定邮件/客户（映射 ProductPromoCode.require_email_or_party）
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 项目集：多对一 -> LoyaltyProgram，必填关系
- usages：一对多 -> CouponUsage，外键 coupon_id
- bound_partners：一对多 -> CouponBoundParty，外键 coupon_id

#### 唯一约束
- 唯一约束 unique_coupon_code：编码

### Conduct（行为声明）

#### 操作
- 创建，可写字段：编码、coupon_type、折扣类型、折扣值、最小订单金额、最大折扣金额、使用限制每编码、使用限制每客户、来源日期、至日期、需求邮箱或参与方，参数：项目集编号：唯一标识（必填）
- 查询
- 更新，可写字段：折扣值、最小订单金额、使用限制每编码、至日期
- 应用（类型：更新），说明：核销优惠券（校验有效性 + 增加 used_count），可写字段：已用数量，参数：订单编号：唯一标识（必填）；伙伴编号：唯一标识
- cancel_coupon（类型：更新），说明：作废优惠券（active -> cancelled）
- 删除

#### 校验
- 创建时，编码 不能为空

#### 变更
- 在 cancel_coupon 时，将 状态 设为 已取消

- 在 创建 / 更新 / 应用 时，将 编号 设为 编号

#### 计算
- 计算字段 实际折扣：金额，规则 计算实际折扣(折扣类型, 折扣值, 最大折扣金额)
- 计算字段 已过期：布尔，规则 check_coupon_expired(至日期)

#### 事件
- 事件：应用 -> loyalty.coupon.已用
- 事件：cancel_coupon -> loyalty.coupon.已取消

#### 工作流
- 流程：coupon_lifecycle_flow：创建 -> 更新 -> 应用 -> cancel_coupon（优惠券发放-使用-核销完整流程）

## 实体：礼品卡（聚合根）

- 说明：礼品卡，记录面值、当前余额、激活状态，支持充值与消费，可作为支付方式
- 来源：基于 产品促销码；来源域 ofbiz/product；过滤条件 用户已录入=是

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 卡编码：文本（必填），说明 礼品卡码（类似优惠码，唯一）
- 置顶编码：文本，说明 安全 PIN（可选，防止未授权使用）
- 状态：枚举（必填），默认值 停用，可选值：停用 / 启用 / depleted / 已过期 / 已取消，说明 礼品卡状态
- 初始余额：金额（必填），必须大于 0（礼品卡面值必须大于0），说明 初始面值
- 当前余额：金额（必填），必须 ≥ 0（礼品卡余额不能为负），说明 当前余额
- 币种编号：文本，说明 货币代码（如 CNY/USD）
- 来源日期：日期时间，说明 生效时间
- 至日期：日期时间，说明 过期时间（映射 ProductPromoCode.thru_date）
- 是否支持充值（reloadable）：布尔，默认值 否
- 实物：布尔，默认值 否，说明 是否实体卡（影响发货逻辑）
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 项目集：多对一 -> LoyaltyProgram
- transactions：一对多 -> 礼品卡交易，外键 礼品卡编号

#### 唯一约束
- 唯一约束 唯一礼品卡编码：卡编码

### Conduct（行为声明）

#### 操作
- 创建，可写字段：卡编码、置顶编码、初始余额、币种编号、来源日期、至日期、reloadable、实物，参数：项目集编号：唯一标识
- 查询
- 启用（类型：更新），说明：激活礼品卡，设置持卡人（inactive -> active），参数：所有者编号：唯一标识（必填）；来源日期：日期时间
- topup（类型：更新），说明：礼品卡充值（reloadable=true 时允许），可写字段：当前余额，参数：金额：金额（必填）；付款参考：文本
- 收费（类型：更新），说明：消费扣款，余额不足则拒绝，可写字段：当前余额，参数：金额：金额（必填）；订单编号：唯一标识
- 取消卡（类型：更新），说明：作废礼品卡（active -> cancelled），余额退款逻辑由外部服务处理
- 过期卡（类型：更新），说明：到期处理（active/depleted -> expired）
- 删除

#### 校验
- 创建时，卡编码 不能为空

#### 变更
- 在 启用 时，将 状态 设为 启用
- 在 取消卡 时，将 状态 设为 已取消
- 在 过期卡 时，将 状态 设为 已过期
- 在 创建 / 更新 / 启用 / topup / 收费 时，将 编号 设为 编号

#### 计算
- 计算字段 用量百分比：金额，规则 初始余额 - 当前余额 ÷ 初始余额 × 100

#### 事件
- 事件：启用 -> loyalty.礼品卡.已激活
- 事件：收费 -> loyalty.礼品卡.charged
- 事件：topup -> loyalty.礼品卡.topup

#### 工作流
- 流程：giftcard_lifecycle_flow：创建 -> 启用 -> topup -> 收费 -> 取消卡 -> 过期卡（礼品卡激活-充值-消费完整流程）
