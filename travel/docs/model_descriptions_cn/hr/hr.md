# 模型业务说明

- 版本：1.0
- 领域：人力
- 领域说明：人力资源领域模型，涵盖员工、部门、岗位、合同、考勤、请假、薪资、绩效、招聘、技能、培训
- 实体数量：27

## 实体：员工（聚合根）

- 说明：员工
- 来源：基于 人员；来源域 ofbiz/party；关联 参与方角色（角色类型编号=员工）

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 工号：文本（必填），说明 工号，全局唯一
- 姓：文本（必填）
- 名：文本（必填）
- 邮箱：文本
- 电话：文本
- 性别：枚举，可选值：男 / 女 / 其他
- 出生日期：日期
- 入职日期：日期（必填）
- 员工类型：枚举，默认值 员工，可选值：员工 / 承包商 / 自由职业者 / 实习生，说明 员工类型
- 状态：枚举，默认值 启用，可选值：启用 / 请假 / 已暂停 / 已终止
- 离职原因：文本，说明 离职原因
- 离职日期：日期，说明 离职日期
- 工作许可到期日：日期，说明 工作许可到期日
- 地址：长文本
- 备注：长文本
- 邮箱已发送：布尔，默认值 否，说明 是否有发送邮件记录（用于在线状态判定）
- IP已连接：布尔，默认值 否，说明 是否有 IP 登录记录（用于在线状态判定）
- 是否手动设置在线（manually_set_present）：布尔，默认值 否
- 在线状态（综合 email/ip/手动 信号判定）（hr_presence_state）：枚举，默认值 待定义，可选值：待定义 / 必填校验 / absent
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 参与方：多对一 -> 参与方，外键 参与方编号，必填关系
- 部门：多对一 -> 部门
- 岗位：多对一 -> 岗位
- 上级：多对一 -> 员工
- 教练：多对一 -> 员工
- 合同：一对多 -> 雇佣合同
- 请假请求：一对多 -> 请假请求
- 考勤：一对多 -> 考勤
- 付款单据：一对多 -> 工资条
- 绩效评审：一对多 -> 绩效审核
- 培训：一对多 -> 培训
- 技能：一对多 -> 员工技能
- 员工技能日志：一对多 -> 员工技能日志
- 恢复明细行：一对多 -> 恢复行
- 工作条目：一对多 -> 工作凭证
- 员工位置：一对多 -> 员工位置

#### 唯一约束
- 唯一约束 唯一员工编码：工号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：工号、姓、名、邮箱、电话、性别、出生日期、入职日期、员工类型、地址、备注，参数：部门编号：唯一标识；岗位编号：唯一标识；上级编号：唯一标识；教练编号：唯一标识
- 查询
- 更新，可写字段：邮箱、电话、地址、状态、备注、员工类型、工作许可到期日
- 终止（类型：更新），说明：离职，清空 parent_id 和 coach_id，记录 departure_date 和 departure_reason，可写字段：离职原因
- 停职（类型：更新），说明：停职
- 重新激活（类型：更新），说明：复职，清空 departure_date 和 departure_reason

#### 校验
- 创建时，工号 不能为空
- 创建时，姓 不能为空
- 终止时，只有在职或休假状态可以离职
- 停职时，只有在职状态可以停职
- 重新激活时，只有停职状态可以复职

#### 变更
- 在 终止 时，将 状态 设为 已终止
- 在 终止 时，将 离职日期 设为 今日
- 在 终止 时，clear_attribute 上级编号
- 在 终止 时，clear_attribute 教练编号
- 在 停职 时，将 状态 设为 已暂停
- 在 重新激活 时，将 状态 设为 启用
- 在 重新激活 时，clear_attribute 离职日期
- 在 重新激活 时，clear_attribute 离职原因
- 在 创建 / 更新 / 终止 / 停职 / 重新激活 时，将 编号 设为 编号

#### 事件
- 事件：终止 -> 人力.员工.已终止
- 事件：创建 -> 人力.员工.创建

#### 工作流
- 流程：employee_write_flow：创建 -> 更新 -> 终止 -> 停职 -> 重新激活（Employee 写操作覆盖流程）

## 实体：请假请求（聚合根）

- 说明：请假申请
- 来源：基于 员工请假；来源域 ofbiz/humanres

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 状态：枚举，默认值 草稿，可选值：草稿 / 确认 / 一级审批 / 验证 / 拒绝，说明 状态: draft=草稿, confirm=已确认, validate1=一级审批通过, validate=最终审批通过, refuse=已拒绝
- 日期来源：日期时间（必填），必须 ≤ 日期（开始时间必须小于等于结束时间），说明 请假开始时间
- 日期：日期时间（必填），说明 请假结束时间
- 单号天数：金额，说明 请假天数（计算字段，基于 employee.resource_calendar 计算工作日天数）
- 单号工时：金额，说明 请假小时数（计算字段，基于工作日历计算总工时）
- 原因：长文本
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 员工：多对一 -> 员工，必填关系
- 请假类型：多对一 -> 请假类型，必填关系
- 首个审批人：多对一 -> 员工
- 第二审批人：多对一 -> 员工

### Conduct（行为声明）

#### 操作
- 创建，可写字段：日期来源、日期、原因，参数：员工编号：唯一标识（必填）；请假类型编号：唯一标识（必填）
- 查询
- 确认操作（类型：更新），说明：确认提交请假申请
- 操作审批（类型：更新），说明：一级审批通过（manager 或 no_validation 类型直接到 validate）
- 操作验证（类型：更新），说明：二级审批通过（仅 both 类型需要，从 validate1 到 validate）
- 操作拒绝（类型：更新），说明：拒绝请假
- 操作草稿（类型：更新），说明：重置为草稿（从 confirm 或 refuse 状态）

#### 校验
- 确认操作时，只有草稿状态可以确认提交
- 操作审批时，只有已确认状态可以审批
- 操作验证时，只有一级审批通过状态可以二级审批
- 操作拒绝时，已拒绝的不能再拒绝
- 操作草稿时，只有已确认或已拒绝状态可以重置为草稿

#### 变更
- 在 确认操作 时，将 状态 设为 确认
- 在 操作审批 时，conditional_set_attribute 状态：一级审批
- 在 操作审批 时，conditional_set_attribute 状态：验证
- 在 操作验证 时，将 状态 设为 验证
- 在 操作拒绝 时，将 状态 设为 拒绝
- 在 操作草稿 时，将 状态 设为 草稿
- 在 操作审批 / 操作验证 时，validate 时创建资源日历请假记录；如 leave_type.create_calendar_meeting=true 则创建日历事件
- 在 操作审批 / 操作验证 时，validate 时若为全天请假，更新 employee.status = on_leave
- 在 创建 / 确认操作 / 操作审批 / 操作验证 / 操作拒绝 / 操作草稿 时，将 编号 设为 编号

#### 事件
- 事件：操作审批 -> 人力.请假.已审批
- 事件：操作验证 -> 人力.请假.已验证

#### 工作流
- 流程：leave_request_write_flow：创建 -> 确认操作 -> 操作审批 -> 操作验证 -> 操作拒绝 -> 操作草稿（LeaveRequest 写操作覆盖流程）
