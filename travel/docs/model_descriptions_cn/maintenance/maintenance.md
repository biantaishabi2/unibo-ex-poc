# 模型业务说明

- 版本：1.0
- 领域：维护
- 领域说明：维护管理领域模型，涵盖设备、车辆、维护请求、维护计划、维修工单、车队管理

## 实体：设备（聚合根）

- 说明：设备，支持 MTBF/MTTR 可靠性指标计算
- 来源：基于 固定资产；来源域 ofbiz/accounting；过滤条件 固定资产类型编号=设备

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 资产编码：文本（必填），说明 设备编号
- 名称：文本（必填），说明 设备名称
- 序列号单号：文本，说明 序列号
- 状态：枚举，默认值 运行中，可选值：运行中 / 维护 / 已退休
- 分类：文本，说明 设备分类
- 位置：文本，说明 存放位置
- 采购日期：日期
- 保修过期日期：日期
- 生效日期：日期，说明 MTBF 计算基线日期
- 备注：长文本
- 维护数量：整数，说明 维护请求总数
- 维护打开数量：整数，说明 未完成、未归档请求数
- 平均修复时间：金额，说明 平均修复时间（天），仅基于 corrective + done 状态的请求
- 平均故障间隔：金额，说明 平均故障间隔（天），仅基于 corrective + done 状态的请求
- 预估下一个失败：日期，说明 预计下次故障日期
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 维护请求：一对多 -> 维护请求
- 分类参考：多对一 -> 设备分类
- 所有者：多对一 -> 参与方，外键 所有者参与方编号
- 技术员：多对一 -> 参与方，外键 技术员参与方编号
- 公司：多对一 -> 参与方，外键 公司参与方编号，必填关系
- 维护团队：多对一 -> 维护团队

#### 唯一约束
- 唯一约束 唯一资产编码：资产编码
- 唯一约束 唯一序列号单号：序列号单号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：资产编码、名称、分类、位置、采购日期、保修过期日期、序列号单号、生效日期、备注
- 查询
- 更新，可写字段：名称、状态、分类、位置、生效日期、备注
- 报废（类型：更新），说明：报废设备

#### 校验
- 创建时，资产编码 不能为空
- 创建时，名称 不能为空
- 报废时，只有运行中或维护中状态可以报废
- company_isolation

#### 变更
- 在 报废 时，将 状态 设为 已退休
- 在 创建 / 更新 / 报废 时，将 编号 设为 编号

#### 工作流
- 流程：equipment_lifecycle：创建 -> 更新 -> 报废（设备生命周期）

- 看板状态：枚举，默认值 正常，可选值：正常 / 完成 / 冻结，说明 看板状态
- 请求日期：日期（必填），默认值 当前时间，说明 提交日期

- 归档：布尔，默认值 否
- 说明：长文本
- 备注：长文本
- 重复间隔：整数，默认值 1，最小值 1，说明 重复间隔
- 重复单位：枚举，默认值 月，可选值：天 / 周 / 月 / 年，说明 重复单位
- 重复类型：枚举，默认值 永久，可选值：永久 / 直到，说明 重复类型

- 周期性维护：布尔，说明 是否周期性维护
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 设备：多对一 -> 设备
- 分类：多对一 -> 设备分类
- 阶段：多对一 -> 维护阶段，必填关系
- 技术员：多对一 -> 参与方，外键 技术员参与方编号
- 所有者：多对一 -> 参与方，外键 所有者参与方编号
- 维护团队：多对一 -> 维护团队
- 公司：多对一 -> 参与方，外键 公司参与方编号，必填关系

#### 唯一约束
- 唯一约束 唯一请求单号：请求单号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：请求单号、名称、维护类型、优先级、说明、请求日期、排班日期、时长、备注、重复间隔、重复单位、重复类型、重复直到，参数：设备编号：唯一标识；分类编号：唯一标识
- 查询
- 更新，可写字段：名称、优先级、看板状态、排班日期、时长、备注、归档
- 变更阶段（类型：更新），说明：变更阶段（看板拖拽），可写字段：阶段编号
- 取消（类型：更新），说明：取消请求

#### 校验
- 创建时，请求单号 不能为空
- 创建时，名称 不能为空
- 创建／更新时，重复直到 不能为空（当重复类型为 until 时，截止日期必填），前提：repeat_type == 'until'

#### 策略
- 权限：创建 操作，当 操作者.角色 属于 维护经理、管理员 时允许
- 权限：查询 操作，当 操作者.角色 = 管理员 或 op=relates_to_actor_via，args=公司 时允许
- 权限：更新 操作，当 操作者.角色 = 管理员 或 op=relates_to_actor_via，args=公司 时允许

#### 变更
- 在 创建 时，将 所有者 设为当前操作人
- 在 创建 时，auto_fill 技术员
- 在 创建 时，auto_fill 维护团队
- 在 创建 时，订阅关注者
- 在 变更阶段 时，重置属性 看板状态：正常
- 在 变更阶段 时，将 关闭日期 设为 now()
- 在 变更阶段 时，clear_attribute 关闭日期
- 在 变更阶段 时，clone_preventive
- 在 创建 / 更新 时，管理活动 排班日期
- 在 创建 / 更新 / 变更阶段 / 取消 时，将 编号 设为 编号

#### 事件
- 事件：变更阶段 -> 维护.请求.已完成（条件 stage.done == true）

#### 工作流
- 流程：maintenance_request_lifecycle：创建 -> 更新 -> 变更阶段 -> 取消（维护请求生命周期）

- 部件延迟：布尔
- 已退回：布尔，说明 关联退货 picking 是否完成

- 公司：多对一 -> 参与方，外键 公司参与方编号，必填关系

- 位置目的：多对一 -> 库存位置，必填关系
- 部件：一对多 -> 维修订单行，外键 维修订单编号

- 查询
- 确认（类型：更新），说明：确认维修 (draft -> confirmed)
- 开始维修（类型：更新），说明：开始维修 (confirmed -> under_repair)
- 完成维修（类型：更新），说明：完成维修 (under_repair -> done)，可写字段：实际成本
- 取消（类型：更新），说明：取消维修 (any -> cancel)
- 重置草稿（类型：更新），说明：重置为草稿 (cancel -> draft)

#### 校验
- 创建时，维修单号 不能为空
- 确认时，只有草稿状态可以确认
- 开始维修时，只有已确认状态可以开始维修
- 完成维修时，只有维修中状态可以完成
- 重置草稿时，只有已取消状态可以重置为草稿
- 确认时，parts_quantity_positive
- 确认时，批号库存检查

#### 变更
- 在 确认 时，将 状态 设为 已确认
- 在 确认 时，确认库存移动
- 在 开始维修 时，将 状态 设为 维修中

- 在 完成维修 时，取消零数量移动
- 在 完成维修 时，创建产品移动
- 在 完成维修 时，操作完成库存
- 在 完成维修 时，同步数量已送达
- 在 取消 时，取消全部库存移动
- 在 取消 时，零销售订单行
- 在 取消 时，将 状态 设为 取消
- 在 重置草稿 时，重置库存移动
- 在 重置草稿 时，恢复销售订单行
- 在 重置草稿 时，将 状态 设为 草稿
- 在 创建 / 更新 时，保修定价
- 在 更新 时，propagate_locations
- 在 创建 / 确认 / 开始维修 / 完成维修 / 取消 / 重置草稿 时，将 编号 设为 编号

#### 事件
- 事件：完成维修 -> 维护.维修.已完成

#### 工作流
- 流程：repair_order_lifecycle：创建 -> 确认 -> 开始维修 -> 完成维修 -> 取消 -> 重置草稿（维修工单生命周期）
