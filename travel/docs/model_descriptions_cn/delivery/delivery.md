# 模型业务说明

- 版本：1.0
- 领域：配送
- 领域说明：物流配送域，管理发货单生命周期、运输路段追踪、包裹管理、 物流行程调度及运费估算规则。基于 OFBiz Shipment 领域建模， 覆盖 B2C/B2B 出货、采购入货、内部调拨、退货等场景。

- 实体数量：18

## 实体：配送（聚合根）

- 说明：物流行程/配送任务，含起止设施、里程、油耗，用于自有车辆配送场景
- 来源：基于 配送；来源域 ofbiz/shipment；过滤条件 

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 配送编号：唯一标识，说明 OFBiz 原始 ID
- 实际开始日期：日期时间，说明 实际出发时间
- 实际到达日期：日期时间，说明 实际到达时间
- 预估开始日期：日期时间，说明 预计出发时间
- 预估到达日期：日期时间，说明 预计到达时间
- 开始里程：金额，说明 出发里程数（km）
- 结束里程：金额，说明 到达里程数（km）
- 燃料已用：金额，说明 燃油消耗量（升）
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 来源设施：多对一 -> 设施，外键 来源设施编号
- 目的设施：多对一 -> 设施，外键 目的设施编号
- 固定资产：多对一 -> 固定资产，外键 固定资产编号
- route_segments：一对多 -> 发货路线段，外键 配送编号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：配送编号、来源设施编号、目的设施编号、预估开始日期、预估到达日期、固定资产编号、开始里程
- 查询
- 更新，可写字段：实际开始日期、实际到达日期、结束里程、燃料已用
- 开始（类型：更新），说明：标记行程已出发，可写字段：实际开始日期、开始里程
- arrive（类型：更新），说明：标记行程已到达，可写字段：实际到达日期、结束里程、燃料已用
- 删除

#### 校验
- 创建时，来源设施编号 不能为空
- 创建时，目的设施编号 不能为空

#### 变更
- 在 创建 / 更新 / 开始 / arrive / 删除 时，将 编号 设为 编号

#### 工作流
- 流程：delivery_trip_flow：创建 -> 开始 -> arrive -> 更新 -> 删除（物流行程生命周期）

- 在 pack 时，将 状态编号 设为 SHIPMENT_PACKED
- 在 发货 时，将 状态编号 设为 发货已发货
- 在 发货 时，将 状态编号 设为 发货已送达
- 在 取消 时，将 状态编号 设为 发货已取消
- 在 创建 / 更新 / 提交 / pick / pack / 发货 / 发货 / 取消 / 删除 时，将 编号 设为 编号

- 计算字段 项数量：整数

## 实体：CrossOrgTransaction（聚合根）

- 说明：跨组织事务编排骨架，串联源销售单、镜像采购单与履约发货链路

### Schema（数据模型）

#### 字段
- 编号：唯一标识（主键、自动生成）
- 交易单号：文本（必填），说明 跨组织事务编号
- 交易类型：枚举（必填），默认值 intercompany_sale_purchase，可选值：intercompany_sale_purchase，说明 首个试点仅覆盖销售单驱动的镜像采购场景
- 状态：枚举（必填），默认值 草稿，可选值：草稿 / 来源已确认 / mirror_created / fulfilled / settled / 失败 / 已取消，说明 事务状态：草稿 -> 源单确认 -> 镜像单生成 -> 履约完成 -> 结算完成
- 结算模式：枚举，默认值 内部发票，可选值：内部发票 / 手动对账，说明 结算模式
- 已计划发货日期：日期时间，说明 计划发运时间
- 镜像单据创建失败原因（mirror_failure_reason）：长文本
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 来源参与方：多对一 -> 参与方，外键 来源参与方编号，必填关系
- 目标参与方：多对一 -> 参与方，外键 目标参与方编号，必填关系
- 来源销售订单：多对一 -> 销售订单，外键 来源销售订单编号，必填关系
- 目标采购订单：多对一 -> 采购订单，外键 目标采购订单编号
- 发货：一对多 -> 发货，外键 cross_org_transaction_id

#### 唯一约束
- 唯一约束 unique_cross_org_transaction_number：交易单号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：交易单号、交易类型、结算模式、已计划发货日期，参数：来源参与方编号：唯一标识（必填）；目标参与方编号：唯一标识（必填）；来源销售订单编号：唯一标识（必填）
- 查询
- 更新，可写字段：结算模式、已计划发货日期
- 确认来源（类型：更新），说明：确认源销售单，允许开始镜像编排
- create_mirror_purchase_order（类型：更新），说明：为对手方创建镜像采购订单，并建立事务关联，参数：目标采购订单编号：唯一标识（必填）
- mark_fulfilled（类型：更新），说明：标记已完成履约
- mark_settled（类型：更新），说明：标记已完成结算
- 标记失败（类型：更新），说明：标记镜像单或履约阶段失败，可写字段：mirror_failure_reason
- 取消（类型：更新），说明：取消跨组织事务

#### 校验
- 创建时，交易单号 不能为空
- 创建时，来源参与方编号 不能等于 arguments.目标参与方编号（source_party_id 与 target_party_id 不能相同）
- 确认来源时，只有草稿状态可以确认源销售单
- create_mirror_purchase_order时，只有源单确认后才允许创建镜像采购单
- mark_fulfilled时，只有镜像单创建完成后才允许标记履约完成
- mark_settled时，只有履约完成后才允许标记结算完成
- 标记失败时，只有编排中的事务才能标记失败
- 取消时，已结算事务不允许取消

#### 变更
- 在 创建 时，将 来源参与方编号 设为 arguments.来源参与方编号
- 在 创建 时，将 目标参与方编号 设为 arguments.目标参与方编号
- 在 创建 时，将 来源销售订单编号 设为 arguments.来源销售订单编号
- 在 确认来源 时，将 状态 设为 来源已确认
- 在 create_mirror_purchase_order 时，通话
- 在 create_mirror_purchase_order 时，将 目标采购订单编号 设为 arguments.目标采购订单编号
- 在 create_mirror_purchase_order 时，将 状态 设为 mirror_created
- 在 mark_fulfilled 时，将 状态 设为 fulfilled
- 在 mark_settled 时，将 状态 设为 settled
- 在 标记失败 时，将 状态 设为 失败
- 在 取消 时，将 状态 设为 已取消
- 在 创建 / 更新 / 确认来源 / create_mirror_purchase_order / mark_fulfilled / mark_settled / 标记失败 / 取消 时，将 编号 设为 编号

#### 事件
- 事件：确认来源 -> delivery.cross_org_transaction.source_confirmed
- 事件：create_mirror_purchase_order -> delivery.cross_org_transaction.mirror_created
- 事件：mark_fulfilled -> delivery.cross_org_transaction.fulfilled
- 事件：mark_settled -> delivery.cross_org_transaction.settled
- 事件：标记失败 -> delivery.cross_org_transaction.failed
- 事件：取消 -> delivery.cross_org_transaction.cancelled

#### 工作流
- 流程：cross_org_transaction_lifecycle：创建 -> 更新 -> 确认来源 -> create_mirror_purchase_order -> mark_fulfilled -> mark_settled -> 标记失败 -> 取消（跨组织事务最小编排闭环）
