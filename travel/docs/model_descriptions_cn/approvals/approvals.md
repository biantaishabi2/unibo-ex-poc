# 模型业务说明

- 版本：1.0
- 领域：审批
- 领域说明：审批管理领域模型，涵盖审批类型、审批请求、审批人记录
- 实体数量：4

## 实体：审批分类（聚合根）

- 说明：审批类型配置，定义审批规则、表单字段和审批人模板
- 来源：基于 工作任务类型；来源域 ofbiz/workeffort；过滤条件 上级类型编号=审批

### Schema（数据模型）

#### 字段
- 编号：整数（主键、自动生成）
- 名称：文本（必填），说明 审批类型名称
- 说明：长文本，说明 类型描述
- 序列编码：文本，说明 自动编号前缀
- 自动化序列：布尔（必填），默认值 否，说明 是否启用自动编号
- 审批最小：整数（必填），greater_than_or_equal_to=0，必须 ≥ 0（最少通过人数不能为负数），说明 最少需通过审批人数
- 经理审批：枚举（必填），默认值 无，可选值：必填 / 可选 / 无，说明 经理审批角色
- 是否启用：布尔（必填），默认值 是，说明 软删除/停用标志
- 排他用户：布尔（必填），默认值 否，说明 是否禁止自审自批
- 请求人文档：长文本，说明 附件说明提示
- 字段配置：jsonb，默认值 ，说明 动态表单字段配置（has_date, has_amount 等，值为 required/optional/no）
- 审批模式：枚举，默认值 并行，可选值：并行 / 顺序 / 混合，说明 多人审批执行模式（Phase 2）
- 工艺路线规则：jsonb，默认值 ，说明 条件路由配置（Phase 2）
- 升级配置：jsonb，默认值 ，说明 超时升级配置（Phase 3）
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 公司：多对一 -> 参与方，外键 公司参与方编号，必填关系
- 审批请求：一对多 -> 审批请求，外键 分类编号

#### 唯一约束
- 唯一约束 唯一名称每公司：名称、公司编号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：名称、说明、序列编码、自动化序列、审批最小、经理审批、排他用户、请求人文档、字段配置、审批模式、工艺路线规则、升级配置，参数：公司编号：整数（必填）
- 查询
- 更新，可写字段：名称、说明、序列编码、自动化序列、审批最小、经理审批、排他用户、请求人文档、字段配置、审批模式、工艺路线规则、升级配置
- 启用（类型：更新），说明：启用审批类型
- 停用（类型：更新），说明：停用审批类型

#### 校验
- 创建时，名称 不能为空
- 启用时，只有停用状态可以启用
- 停用时，只有启用状态可以停用

#### 变更
- 在 启用 时，将 是否启用 设为 是
- 在 停用 时，将 是否启用 设为 否
- 在 创建 / 更新 / 启用 / 停用 时，将 编号 设为 编号

#### 工作流
- 流程：approval_category_lifecycle_flow：创建 -> 更新 -> 停用 -> 启用（审批类型完整生命周期流程）
- 流程：approval_category_deactivate_flow：创建 -> 更新 -> 停用（审批类型停用流程）

## 实体：审批请求（聚合根）

- 说明：审批请求单，关联审批类型并管理审批生命周期
- 来源：基于 工作任务；来源域 ofbiz/workeffort；过滤条件 工作工作量类型编号=审批

### Schema（数据模型）

#### 字段
- 编号：整数（主键、自动生成）
- 名称：文本（必填），说明 请求标题/编号
- 状态：枚举（必填），默认值 新，可选值：新 / 待处理 / 已审批 / 已拒绝 / 取消，说明 请求状态
- 请求日期：日期，说明 提交日期（submit 时自动填充）
- 日期已确认：日期时间，说明 最终审批/拒绝时间戳
- 元数据：jsonb，默认值 ，说明 动态字段（金额、日期、地点、数量、参考编号等）
- 原因：长文本，说明 申请说明
- 附件编号列表：列表，默认值 ，说明 关联附件 ID 列表
- 创建时间：日期时间（自动生成）
- 更新时间：日期时间（自动生成）

#### 关系
- 分类：多对一 -> 审批分类，必填关系
- 请求人：多对一 -> 参与方，外键 请求人参与方编号，必填关系
- 公司：多对一 -> 参与方，外键 公司参与方编号，必填关系
- 审批人：一对多 -> 审批人，外键 请求编号，管理模式 直接管理

### Conduct（行为声明）

#### 操作
- 创建，可写字段：名称、原因、元数据、附件编号列表，参数：分类编号：整数（必填）；公司编号：整数（必填）
- 查询
- 提交（类型：更新），说明：提交审批
- 审批（类型：更新），说明：审批通过（系统根据审批人状态自动触发）
- 拒绝（类型：更新），说明：审批拒绝（系统根据审批人状态自动触发）
- 取消（类型：更新），说明：申请人取消请求
- 草稿（类型：更新），说明：重置为草稿（从 refused/cancel 状态回退）

#### 校验
- 创建时，名称 不能为空
- 提交时，只有草稿状态可以提交
- 审批时，只有待审批状态可以通过
- 拒绝时，只有待审批状态可以拒绝
- 取消时，只有待审批状态可以取消
- 草稿时，只有拒绝或取消状态可以重置为草稿

#### 变更
- 在 创建 时，将 请求人 设为当前操作人
- 在 提交 时，将 状态 设为 待处理
- 在 提交 时，将 请求日期 设为 今日
- 在 审批 时，将 状态 设为 已审批
- 在 审批 时，将 日期已确认 设为 当前时间
- 在 拒绝 时，将 状态 设为 已拒绝
- 在 拒绝 时，将 日期已确认 设为 当前时间
- 在 取消 时，将 状态 设为 取消
- 在 草稿 时，将 状态 设为 新
- 在 草稿 时，设置 请求日期
- 在 草稿 时，设置 日期已确认
- 在 创建 / 提交 / 审批 / 拒绝 / 取消 / 草稿 时，将 编号 设为 编号

#### 计算
- 计算字段 已审批数量：整数，规则 数量(审批人（条件: 状态 = 已审批）)
- 计算字段 全部必填已审批：布尔，规则 all?(审批人（条件: 必填 = 是）, 状态 = 已审批)

#### 事件
- 事件：提交 -> 审批.请求.已提交
- 事件：审批 -> 审批.请求.已审批
- 事件：拒绝 -> 审批.请求.已拒绝
- 事件：取消 -> 审批.请求.已取消

#### 工作流
- 流程：approval_request_approve_flow：创建 -> 提交 -> 审批（审批请求正常通过流程）
- 流程：approval_request_refuse_resubmit_flow：创建 -> 提交 -> 拒绝 -> 草稿 -> 提交（审批请求拒绝后重新提交流程）
- 流程：approval_request_cancel_flow：创建 -> 提交 -> 取消 -> 草稿（审批请求取消流程）

## 实体：审批人

- 说明：审批人记录，跟踪每个审批人对请求的审批状态
- 来源：基于 工作任务参与方分配；来源域 ofbiz/workeffort

### Schema（数据模型）

#### 字段
- 编号：整数（主键、自动生成）
- 状态：枚举（必填），默认值 新，可选值：新 / 待处理 / 已审批 / 已拒绝 / 取消，说明 审批人状态
- 必填：布尔（必填），默认值 否，说明 是否为必须审批人
- 角色：文本，说明 审批人角色（如 direct_manager）
- 评论：长文本，说明 审批意见（refuse 时填写）
- 审批日期：日期时间，说明 做出决定的时间
- 编辑：布尔（必填），默认值 否，说明 是否可编辑请求内容
- 序列订单：整数，说明 串行审批时的执行顺序（Phase 2）
- 委派状态：枚举，可选值：待处理 / 已解决，说明 委派状态（Phase 2）
- 已升级来源编号：整数，说明 升级来源审批记录（Phase 3）
- 截止日：日期时间，说明 审批截止时间（Phase 3）

#### 关系
- 用户：多对一 -> 参与方，外键 用户参与方编号，必填关系
- 请求：多对一 -> 审批请求，必填关系
- 已委派来源：多对一 -> 参与方，外键 已委派来源参与方编号

#### 唯一约束
- 唯一约束 唯一用户每请求：请求编号、用户编号

### Conduct（行为声明）

#### 操作
- 创建，可写字段：用户编号、必填、角色、编辑、序列订单，参数：请求编号：整数（必填）
- 查询
- 审批（类型：更新），说明：审批通过，可写字段：评论
- 拒绝（类型：更新），说明：审批拒绝，可写字段：评论
- 取消（类型：更新），说明：取消（随 request 取消批量设置）
- 草稿（类型：更新），说明：重置为初始状态（随 request 重置批量设置）

#### 校验
- 审批时，只有待审批状态可以通过
- 拒绝时，只有待审批状态可以拒绝

#### 变更
- 在 启用 时，将 状态 设为 待处理
- 在 审批 时，将 状态 设为 已审批
- 在 审批 时，将 审批日期 设为 当前时间
- 在 拒绝 时，将 状态 设为 已拒绝
- 在 拒绝 时，将 审批日期 设为 当前时间
- 在 取消 时，将 状态 设为 取消
- 在 草稿 时，将 状态 设为 新
- 在 草稿 时，设置 审批日期
- 在 草稿 时，设置 评论
- 在 创建 / 审批 / 拒绝 / 取消 / 草稿 时，将 编号 设为 编号

#### 事件
- 事件：审批 -> 审批人已审批
- 事件：拒绝 -> 审批人已拒绝

#### 工作流
- 流程：approver_approve_flow：创建 -> 审批（审批人通过流程）
- 流程：approver_refuse_flow：创建 -> 拒绝（审批人拒绝流程）
- 流程：approver_cancel_reset_flow：创建 -> 取消 -> 草稿（审批人取消并重置流程）
