# 京东商品 + 商旅一体化方案提案

## 1. 项目背景与项目定义

京东当前面向企业客户的两类能力分属不同团队和系统：
- 锦礼/商品能力一套
- 商旅/酒店能力一套

客户侧的真实诉求不是分别采购和使用两套系统，而是希望以统一入口获得“商品 + 酒店/商旅”的一体化能力。

我们此前已经具备与京东 VOP 体系的对接经验，因此本次工作的目标不是重建京东既有底座，而是在现有能力基础上完成商品与商旅能力的整合交付，并补齐企业客户场景中关键但当前相对薄弱的能力模块，尤其是：
- 企业审批
- 差旅管控
- 核心流程闭环

因此，本项目本质上是一次面向企业客户交付的一体化方案整合与增强，而不是单一商旅子系统的孤立建设。

## 2. 现状系统、既有能力与主要短板

### 2.1 京东现有能力

- 商品能力已有独立系统与交付链
- 商旅能力已有独立系统与交付链
- 面向企业客户已有一定商旅客户基础
- 内部销售与客户交付链路已存在

### 2.2 我们已有能力

- 已有 VOP 对接经验
- 已有 Travel POC 作为方案原型
- 已沉淀审批、差标、订单与履约相关建模和页面能力

### 2.3 当前主要短板

- 商品与商旅仍是分开的系统与交付方案
- 企业审批与差旅管控能力相对薄弱
- 面向客户的一体化产品表达不足
- 后续客户化交付缺少统一的平台底座与标准边界

本次工作的价值，不是替京东推翻重做底座，而是在既有底座之上补一层可销售、可交付、可扩展的企业差旅方案层。

## 3. 本次方案目标与交付边界

### 3.1 本次目标

- 形成商品 + 商旅的一体化方案底座
- 补齐企业审批、差旅管控、关键流程闭环能力
- 形成可统一展示、统一销售、统一交付的解决方案骨架
- 为后续客户项目实施提供复用底座

### 3.2 本次不包含

- 不一次性覆盖所有客户的个性化需求
- 不一次性完成所有 OA / 财务 / 报销 / ERP 深度联调
- 不一次性覆盖所有商旅品类与所有供应商
- 不把后续客户实施工作隐含打包进本次平台建设范围

这次交付的重点是平台能力建设，而不是所有客户场景的完整落地。

## 4. 方案结构与能力补齐点

### 4.1 方案结构

整体方案建议分成四层：
- 商品能力层
- 商旅能力层
- 企业审批/差标/管控层
- 宿主接入层与客户系统集成层

### 4.2 本次重点补齐能力

- 商品与商旅的一体化入口与流程组织
- 差旅审批能力
- 差标与超标策略
- 改签、退票、履约等企业差旅关键流程
- 面向企业客户的统一方案表达

### 4.3 对京东价值

- 把现有商品能力与商旅能力打包成统一方案
- 补强现有商旅能力中最影响企业成交的短板
- 形成后续客户项目可复用、可扩展的平台基础

## 5. 本次交付清单、交付物与阶段划分

### 5.1 本次交付清单

- 平台代码与模型
- 核心页面与流程
- 商品/商旅/审批相关 bridge 与运行时接入
- 提案与实施文档
- 测试、验收与演示材料

### 5.2 建议阶段划分

1. 方案收口与模型确认
2. 核心平台能力补齐
3. 页面与流程打通
4. 演示版本与验收交付

### 5.3 交付结果定义

首期交付应被定义为：
- 一套可演示、可继续客户化实施的平台底座
- 而不是一次性包完所有最终客户定制项

## 6. 商务合作方式与报价口径

### 6.1 合作方式建议

建议采用两阶段合作模式：

第一阶段：
- 收取平台建设费
- 完成一体化方案底座建设

第二阶段：
- 京东后续每落一个具体客户
- 再按客户需求单独评估、单独报价、单独实施

### 6.2 报价口径建议

本次不按“单卖源码”口径报价，而按“平台建设与交付能力”报价。

后续客户项目应单独计费，包括但不限于：
- 客户化页面与流程
- OA / 财务 / 报销 / ERP 集成
- 组织权限与审批规则定制
- 特定供应商与渠道对接

### 6.3 商务边界

- 平台建设费对应平台底座与方案能力
- 客户项目费用对应客户实施与定制交付
- 平台升级与客户项目实施应拆分管理、拆分报价

## 7. 非目标、风险与后续客户化实施方式

### 7.1 非目标

- 不在首期覆盖全部客户场景
- 不在首期完成所有深度系统集成
- 不承诺无限制客户化修改

### 7.2 风险

- 京东内部商品与商旅系统边界可能继续调整
- 企业客户审批/财务流程差异较大
- 真实供应商联调与企业系统联调会拉高项目复杂度

### 7.3 后续客户化实施方式

建议采用“平台底座 + 客户项目”的长期合作方式：

- 平台层负责统一能力沉淀
- 客户层按具体需求实施
- 后续新增能力、变更需求与深度集成通过新项目或新阶段承接

这样可以同时保证：
- 首期边界清晰
- 后续扩展有路径
- 商务模型可持续
